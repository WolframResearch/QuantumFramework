# Structured arrays in QF: operation-by-operation benchmark table

Each row: the operation as a formula; the code QF runs today (file:line in `QuantumFramework/Kernel`); the candidate code with a structured head; and the time, QF → new. Times are measured only at the size where QF's current code takes ≥ 1 s, and pushed up to where either side exceeds 60 s or 8 GB.

**How the times were measured (2026-09-25):**
- WL 15.0.1 (the default `wolframscript` kernel on 2026-09-25) on the working tree, one fresh kernel per group of rows; the `Cos` bug and row 8 were also checked on 15.0.0.
- QF's property cache is left on. The QF time is the first call on a freshly built operator, and the second call is reported where it differs.
- The structured code is timed as the minimum of 3 runs, each after `ClearSystemCache[]`.
- The machine was loaded throughout: other sessions' kernels at 60-100% CPU (PIDs 54937, 79593, 79595, 79627, 79865, 80022, …). This inflates QF's seconds somewhat, but not by the 10²-10⁴ factors in the table. Before the numbers are published, rows 1, 5 and 7 should be rerun on an idle machine.
- Only sizes where QF takes ≥ 1 s are listed as results.

Every row's candidate agrees with QF's result: identical spectra, or outputs within 1e-13. Conventions were checked first: `"X"[d]` = `PermutationMatrix[RotateRight[Range[d]]]`; QF's Fourier basis matrix = `FourierMatrix[d]`; the change of basis computes `Inverse[F] . v`.

## How each row is timed (rules fixed before any run)

1. **Quiet machine:** `ps` shows no other `WolframKernel` or `wolframscript` process; a fresh kernel per row.
2. **Correctness first:** the candidate matrix equals QF's matrix (exact where QF is exact), and the outputs agree (exact, or to 1e-10 for machine numbers).
3. **Timing:** inputs built outside the timed part (build cost recorded separately); `ClearSystemCache[]` before each repeat; minimum of 3 repeats; the result is forced as QF would use it (e.g. the exponential then applied to a state).
4. **Size sweep:** add a qubit until QF's current code takes ≥ 1 s. Time both from there, and keep adding qubits until either side exceeds 60 s or 8 GB (`TimeConstrained`, `MemoryConstrained`, messages recorded through `EvaluationData`, no `Quiet`).
5. **Reported in the last column:** at each size where QF ≥ 1 s, QF seconds → new seconds, plus the largest n each side reaches within 60 s / 8 GB. A row counts as an improvement only if it saves ≥ 1 s per call, or turns an impossible size into a feasible one.
6. **Raw timings are saved,** so every entry can be recomputed.

After the table is filled, the kernel-change plan is written from the rows that pass, citing the row for each change.
