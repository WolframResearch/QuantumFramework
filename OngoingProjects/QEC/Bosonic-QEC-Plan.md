# Symbolic Bosonic Quantum Error Correction: a plan

*Companion to `QEC-Development-Plan.md` and `QEC-Roadmap-2026-09.md`, which cover the
qubit (discrete-variable) stabilizer codes. This plan opens the sibling branch the qubit
layer has nothing in: error-correcting codes that hide a qubit inside a bosonic mode,
analyzed exactly and symbolically. It is written to sit on the `SecondQuantization`
bosonic layer already in the paclet, and it is scoped by a literature and GitHub audit
(September 2026) that ruled out the obvious first idea, confirmed the chosen one, and
sharpened it.*

A bosonic code hides a logical qubit in the infinite-dimensional Hilbert space of one (or
a few) harmonic oscillators, in a subspace chosen so that the physical errors that
actually occur (photon loss, dephasing, small phase-space displacements) push the state
in a way we can detect and undo. A code protects against a given error set exactly when
the Knill-Laflamme conditions hold on its codewords. For the codes built from a
displacement or a rotation symmetry, those conditions collapse to a handful of
closed-form identities in special functions. That collapse is the thing a computer-algebra
system does better than anything else, and it is what this plan builds.

---

## 1. What the audit settled (read before choosing a target)

The tempting first target does not survive the literature:

- **Do not derive the square-lattice GKP logical error rate.** It is textbook. Gottesman,
  Kitaev and Preskill state it; Conrad, Eisert and Arzani cast it as Voronoi-cell lattice
  sums; Matsuura, Yamasaki and Koashi give the finite-energy theta-function overlaps in
  closed form. A computer-algebra derivation of the ideal square Gaussian rate is a
  reproduction, not a contribution.
- **Do not rebuild the phase-space toolkit.** The Wigner-function machinery for GKP on any
  lattice already exists (Mensen, Baragiola and Menicucci).
- **The gap the audit confirmed:** no tool, in any language, checks the Knill-Laflamme
  conditions or analyzes a bosonic code symbolically in closed form. Bosonic-code
  simulators are numerical; symbolic packages do operator algebra but no code analysis;
  the qubit QEC verifiers check programs and circuits, not closed-form conditions on
  bosonic codewords. The full landscape is in the last section.

The one thing that is genuinely ours: exact and symbolic, small and closed-form. It is the
same niche the qubit QEC layer keeps against Stim, moved to the bosonic setting where
every existing tool is a numerical simulator.

## 2. What to build

Ordered the way the physics builds up. Each item says what the physics is, the concrete
Wolfram Language object that delivers it, and what Bruno should read for it.

### (a) The code object and its Knill-Laflamme conditions. The core.

*Physics.* An error channel comes with a set of error operators (its Kraus operators):
photon loss on one mode is generated by powers of the annihilation operator `a`, dephasing
by powers of the number operator `a\[Dagger]a`. A code with codewords `|W_i>` corrects an
error set `{E_a}` exactly when the Knill-Laflamme conditions hold: the matrix of overlaps
`<W_i| E_a\[Dagger] E_b |W_j>` equals `h_ab \[Delta]_ij`, a Hermitian coefficient matrix
`h_ab` that does not depend on which codeword. When the code carries a rotation or
displacement symmetry, those overlaps are closed-form: cat codewords are sums of coherent
states, whose overlaps `<\[Alpha]|\[Beta]>` are Gaussian exponentials; binomial codewords
are finite Fock-state sums, whose overlaps are finite hypergeometric sums. The
Knill-Laflamme conditions then become a small set of exact identities in special functions
rather than a numerical linear-algebra check on a truncated Fock space.

*Deliver.* A bosonic code object, built from its codewords (a Fock-state sum, a
coherent-state sum, or a symbolic form), that: reports the error set of a named channel
(loss, dephasing, pure displacement) to a chosen order; assembles the Knill-Laflamme
matrix symbolically; decides exact correctability, or, for an approximate code, the
leading order in the loss or dephasing rate to which the conditions hold; and returns the
Knill-Laflamme coefficient matrix itself (the Hermitian `h_ab`) with a signature read off
it, so a code is described by an exact invariant and not only a yes or no. The matrix
elements are produced by feeding the codewords through the `SecondQuantization` machinery
Bruno already owns (`BosonicNormalOrder`, `ExpBosonOrder`, the vacuum-expectation and
displacement algebra); `HypergeometricPFQ`, the theta functions, and exact linear algebra
close and prove them. Idiom: build the overlap matrix with `Table` / `Outer` over the
codeword and error indices, reduce with `FullSimplify` under the code's assumptions, and
test the identity with `PossibleZeroQ`, never a numerical tolerance.

*First concrete milestone.* Derive, symbolically and in closed form, that the smallest
binomial code (parameters N = 1, S = 1, of Michael et al.), with codewords
`(|0> + |4>)/Sqrt[2]` and `|2>`, corrects a single photon loss exactly: for the error set
`{I, a}` the coefficient matrix is `h = {{1, 0}, {0, 2}}`, diagonal by photon-number parity
and codeword-independent by balanced mean photon number, an exact identity rather than a
number. Then the two-component and four-component cat codes under the same error set. All
three are hand-derived in the literature; the deliverable is that the tool derives them,
and then reports the order to which each holds as the loss order grows.

*Study.* The Knill-Laflamme conditions themselves: Nielsen and Chuang chapter 10, and
Knill and Laflamme, *Theory of quantum error-correcting codes*, Phys. Rev. A **55**, 900
(1997). The bosonic-code families and their conditions:
[[Mic16]](https://doi.org/10.1103/PhysRevX.6.031006) (binomial codes),
[[Alb17b]](https://doi.org/10.1103/PhysRevA.97.032346) (structure of single-mode bosonic
codes, where the Knill-Laflamme-as-moment-conditions reduction is laid out), and
[[Gri19]](https://doi.org/10.1103/PhysRevX.10.011058) (rotation-symmetric codes, the
unifying frame for cat and binomial). The coefficient matrix as an object of study in its
own right: Du et al., [[Du24d]](https://doi.org/10.1038/s41534-025-01155-1), which does
exactly this symbolically for finite-dimensional qubit codes and is the template to carry
into the bosonic setting. The oscillator and phase-space algebra underneath:
[[Wee11]](https://doi.org/10.1103/RevModPhys.84.621) (Gaussian quantum information review)
and Cahill and Glauber, [[Cah69]](https://doi.org/10.1103/PhysRev.177.1857) (ordered
operator expansions, the s-ordering his `SOrderedRepresentation` already implements).

### (b) Code discovery by exact algebraic conditions. The novelty fork.

*Physics.* Turn the Knill-Laflamme conditions around. Instead of checking a given code,
solve for the codewords that satisfy them. For a symmetry-defined family this is a system
of moment or design equations, polynomial in the codeword coefficients. Victor Albert's
group and the Leverrier-Vuillot group have made this concrete and handed it to algebra:
the Tiger codes have codeword overlaps governed by Gelfand-Kapranov-Zelevinsky
hypergeometric functions and a finite generating set; quantum spherical codes impose
spherical-design conditions on a coherent-state constellation; quantum cubature codes
generalize that to weighted multishell moment equations. In every case the code conditions
are already written as exact algebraic constraints. What is missing is the general
symbolic solver applied to them.

*Deliver.* A solver that takes an error set, a symmetry, and an energy or Fock-support
budget, and returns the codewords satisfying Knill-Laflamme to a chosen order, by `Solve`
and `GroebnerBasis` over the exact algebraic conditions rather than by numerical search
over a truncated space. This is where the Wolfram Language does what a sampler cannot:
exhaust or parametrize the solution family exactly, and prove a family empty when it is.
The audit found the opening bluntly: the papers formulate the conditions algebraically but
none brings a general Groebner, resultant, or holonomic (creative-telescoping) engine to
them, which is exactly Wolfram's stack. The qubit precedent already exists: Du et al. solve
the Knill-Laflamme polynomial system symbolically and trace continuous code families by
it; the bosonic analog is open.

*Study.* The algebraic-design families: [[Xu24b]](https://doi.org/10.1103/ls5r-vj7r) and
[[Poi26]](https://arxiv.org/abs/2607.22460) (Tiger codes and their algebraic structure),
[[Jai23]](https://doi.org/10.1038/s41567-024-02496-y) (quantum spherical codes),
[[Yan25]](https://arxiv.org/abs/2511.23316) (quantum cubature codes), and
[[Ayd25b]](https://doi.org/10.48550/arXiv.2509.20545) (codes from convex geometry). The
Knill-Laflamme-solving precedent for qubit codes:
[[Du24d]](https://doi.org/10.1038/s41534-025-01155-1). For the special-function side, C.
Koutschan's `HolonomicFunctions` Mathematica package (RISC, JKU Linz), the closed-form
engine for the hypergeometric overlaps.

### (c) Channel-adapted recovery and exact logical channels. The impact fork.

*Physics.* Correctability is half the story; the recovery map and the residual logical
channel are the other half. The optimal recovery is usually a semidefinite program,
numerical by construction. The one analytic handle is the transpose (Petz) channel, which
is near-optimal for approximate codes and has been used analytically for GKP under loss.
Carrying the transpose channel and the resulting logical channel to closed form for
finite-energy cat, binomial and loss-dephasing codes is open. It is also the part closest
to the open-systems and stochastic-master-equation work already in `OngoingProjects`: the
exact logical Lindbladian, including leakage out of the code space, is on the same list of
openings.

*Deliver.* Symbolic transpose-channel recovery for a given code and channel; the residual
logical channel as a closed-form process (its Pauli-transfer matrix or its Kraus form);
and, where the code is held by engineered dissipation, the exact logical Lindbladian. This
reuses the `SecondQuantization` phase-space and covariance-matrix machinery and ties the
bosonic-code branch to the stochastic-master-equation work.

*Study.* [[Ben09]](https://doi.org/10.1103/PhysRevLett.104.120501) (general conditions for
approximate quantum error correction and near-optimal recovery) and Barnum and Knill,
[[Bar00]](https://doi.org/10.1063/1.1459754) (reversing quantum dynamics, the transpose
channel). For the transpose channel applied to bosonic loss:
[[Zhe24b]](https://arxiv.org/abs/2412.06715) and
[[Har25c]](https://doi.org/10.1103/rmlm-vbfd). For codes protected by engineered
dissipation: Mirrahimi et al., [[Mir13]](https://doi.org/10.1088/1367-2630/16/4/045014)
(dynamically protected cat qubits).

## 3. What this is not

Not a bosonic circuit simulator: Strawberry Fields, Bosonic Qiskit and MrMustard own Fock
and Gaussian simulation, and Bosonic Pauli+ owns concatenated-GKP sampling. Not a
numerical decoder or threshold estimator. The edge is the exact closed form those tools
can only approach by truncation and sampling, and the boundary is the one the qubit layer
already keeps against Stim: connect to the numerical tools, do not rebuild them.

Not, at least not first, GKP. It is the most-worked and most-solved analytical corner of
the field. The symmetry-defined single-mode codes and the code-discovery problem are where
symbolic computation is both known to be tractable and not yet built into any tool.

---

## 4. Order of work

1. The code object and symbolic Knill-Laflamme (a), through the binomial and cat
   milestones. Nothing else is worth starting until a code's correctability is a symbolic
   identity that the tool produces on its own. A one-page spec for this part, with concrete
   function signatures and the binomial worked example, is in `Bosonic-QEC-PartA-Spec.md`.
2. Then one fork, by appetite: (b) code discovery for novelty, or (c) channel-adapted
   recovery for impact and for the tie to the open-systems work.
3. Fold the result into the QEC project as its bosonic sibling: a shared frame (code as a
   subspace, an error set, a correctability question, a logical channel), a separate object
   from the qubit `QECCode`.

## Prior art and tooling (audit, September 2026)

Three literature searches and a GitHub sweep. The finding that matters: **no tool, in any
language, checks the Knill-Laflamme conditions or analyzes a bosonic code symbolically in
closed form.** The space around the niche, so as not to re-derive or rebuild it:

- **GKP, the solved analytical corner** (do not reproduce): the original code
  [[Got00b]](https://doi.org/10.1103/PhysRevA.64.012310), the lattice perspective
  [[Con21c]](https://doi.org/10.22331/q-2022-02-10-648), the finite-energy theta-function
  overlaps [[Mat19b]](https://doi.org/10.1103/physreva.102.032408), and the phase-space
  toolkit [[Men20]](https://doi.org/10.1103/PhysRevA.104.022408).
- **Numerical bosonic-code simulators** (connect, do not rebuild):
  [[Kil18]](https://doi.org/10.22331/q-2019-03-11-129) (Strawberry Fields),
  [[Sta22b]](https://doi.org/10.1109/HPEC55821.2022.9926318) (Bosonic Qiskit),
  [[Hop24]](https://doi.org/10.22331/q-2024-11-26-1539) (Bosonic Pauli+), and the JAX-based
  `EQuS/bosonic` (github.com/EQuS/bosonic, now archived in favor of `jaxquantum`). All
  numerical.
- **Symbolic operator-algebra engines** (substrate, none does code analysis): in Python,
  QuAlg [[Dah20]](https://arxiv.org/abs/2008.06467), pyBoLaNO
  [[Lim25b]](https://doi.org/10.1016/j.cpc.2025.109622), SymQuPS
  [[Lim26]](https://arxiv.org/abs/2608.14263); in the Wolfram Language, `Q3`
  (github.com/quantum-mob/Q3) and `sneg` (github.com/rokzitko/sneg); in Julia,
  `SecondQuantizedAlgebra.jl`. The QuantumFramework `SecondQuantization` layer is this
  project's own engine and the reason to build here rather than on those.
- **Qubit QEC verifiers** (adjacent, none is a bosonic Knill-Laflamme checker): Veri-QEC
  [[Hua25b]](https://doi.org/10.1145/3729293), the symbolic-execution verifier
  [[Fan23b]](https://doi.org/10.1145/3656419), QECV
  [[Wu21]](https://arxiv.org/abs/2111.13728), Quantomatic on the Steane code
  [[Dun13]](https://doi.org/10.4204/EPTCS.171.4), the symbolic exact simulator SyQMA
  [[Umb26]](https://arxiv.org/abs/2604.15043), and the older Mathematica QEC simulation of
  Gerdt and Prokopenya [[Ger13]](https://doi.org/10.1007/978-3-319-02297-0_9). Every one is
  qubit or stabilizer centric and verifies programs or circuits, not closed-form
  Knill-Laflamme conditions on arbitrary bosonic codewords.

A caveat worth stating plainly: Victor Albert's group is prolific in the algebraic-code
direction (Tiger, spherical, cubature, and convex-geometry constructions), so the
conceptual frontier of part (b) has strong competition. The Wolfram angle, a general
symbolic solver (Groebner, holonomic, special functions) applied to code conditions others
have only written down, together with the `SecondQuantization` operator algebra, is the
differentiator.
