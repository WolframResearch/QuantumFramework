Bulk stabilizer plan builder — final results

Implementation
Production changes are confined to QuantumFramework/Kernel/Stabilizer/GateMatrix.m on existing main. Nothing is staged or committed. The builder uses PositionIndex on physical local data, an immutable Dispatch of exact reference matrices, batched Part/Thread/Transpose wire remapping, and SortBy/Catenate to restore circuit order. Labels and absolute wires are excluded from group identity; basis, picture and order permutations are retained. Only exact matching canonical local data uses the primitive lookup; other matrices keep the general classifier. Symbolic/composite token recovery and refusals remain per occurrence.

Correctness
Fresh final suite: 1667/1667 tests across 16 files; no failures or outside messages. BulkPlanBuilder.wlt adds 56 regressions. The first independent round found an active-constructor evaluation defect in a nested LHS pattern; the revised helper uses the existing QF-style typed object boundary and Part extraction. New execution contracts detect unevaluated fingerprints and skipped primitive lookup. The second fresh round independently checks C/WVM, exact/numeric dense adjoint action through 5 qubits, symbolic signs/phases, malformed/refusal regimes, packed boundaries through 1,024 and 12,000 gates. See ReviewRound1.md and ReviewRound2.md for final verdict/evidence.

Benchmark definition
Seven alternating Before/After trials per row in one Wolfram 15.0.1 ARM64 C-target kernel, after correctness kernels exited. Before reconstructs the exact baseline flat-operator mapper from commit 89051701; all other production source and the compiled fold are identical. Every timed trial starts with ClearSystemCache[]. Cold clears all six stabilizer engine caches. Warm primes the selected plan first. QF property caches and the loaded runtime are already warm. Ordinary rows exclude native compilation and the one-time immutable primitive-table initialization; FirstPlan rows explicitly restore its delayed initializer before the timed After call. Neither row measures fresh process startup.
The 10,000-gate public workloads are ten applications of a prebuilt 1,000-gate block. Cold means the first application starts with cold engine caches; the following nine reuse its plan. Random cases repeat a fixed-seed random 1,000-gate block. Direct controls evolve 10,000 gate specifications in one call. Circuit construction, wire-metadata preparation and expanded-tableau/sign hashing are outside evolution timing. These measurements do not establish throughput for a single flat 10,000-operator QCO or ten unrelated one-use circuits. Large QCO construction/FullInputOrder preparation was costly in untimed probes and is outside this production change.
The matrix-backed general classifier is already cached per distinct gate; the gain comes from removing per-occurrence extraction/classification lookup/remapping work and recognizing verified primitives. This is a bulk plan change, not another circuit cache.

Reproduce
Run '/Applications/Wolfram 15.01.app/Contents/MacOS/WolframKernel' -noinit -script <audit-directory>/RunFullSuite.wls with STABILIZER_AUDIT_PHASE=reproduced to rerun all stabilizer tests. Run PairedBulkPlanBenchmark.wls with STABILIZER_BULK_OUTPUT=<desired-json-path>. Run correctness and timing kernels serially for performance work. The baseline GateMatrix snapshot and manifest bind the comparison to source bytes.

The independent cold-plan speedups are 3.22x at 128 qubits and 2.82x at 1,024 for this recipe. Warm public medians improve modestly; no universal warm gain is claimed. Parent recipe plans contain 2,001 baseline encoded instructions versus 1,290 (128 qubits) or 1,286 (1024) after verified primitive recognition, so a real modest public warm benefit is possible without altering the native fold.
